# Feature specification template

Status: Proposed. Owner, date, related issue/design and affected platforms: fill explicitly.
Copy for a real feature; this template itself approves no product behavior.

## Problem and outcome

User, situation, pain and intended observable improvement. State scope boundaries.

## Current implementation

Relevant entry point/state/data paths and confirmed behavior. Separate existing code facts
from the desired behavior. Link actual Figma nodes and representative components.

## Behavior contract

Describe starting states, actions, transitions, results and error/retry behavior. Cover
permission, offline, concurrent/repeated actions and account/lifecycle changes when relevant.

## Acceptance criteria

| Given | When | Then | Platform / verification |
| --- | --- | --- | --- |
| Fill real case | Fill action | Observable result | Test/manual scenario |

## Technical impact

Modules, API/schema/storage, native integration, accessibility, assets and measurement.
Identify migrations and old-client compatibility; link ADR for a significant accepted tradeoff.

## Delivery evidence and questions

Actual checks, rollout/recovery if applicable, known limitations and unresolved product decisions.
