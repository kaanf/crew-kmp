# Architecture decision records

Record significant accepted technical tradeoffs: module boundaries, public APIs,
storage/migrations, major dependencies or framework integration. Do not create an ADR
for every refactor. Existing decisions remain authoritative until explicitly superseded.

Copy [ADR_TEMPLATE](ADR_TEMPLATE.md) to a numbered descriptive filename. Use Proposed,
Accepted, Rejected or Superseded status, with the real date and owner. Link replacements
when superseding decisions. Do not invent historical approvals from the current code.
